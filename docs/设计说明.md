# 电商数据分析 Agent 设计说明

## 目标

以本地 Qwen LoRA SFT 微调为核心，在独立人工测试集上比较同一基础模型微调前后的效果，并将 LoRA 模型接入单个 Text-to-SQL Agent。API 教师、API 裁判和三方评估作为可选的数据扩充与能力参考，不是项目运行的必要条件。

## 架构

```text
人工问题、固定业务规则和标准 SQL
  -> 可选：API 教师改写问题并由 API 裁判过滤
  -> 本地 Qwen LoRA 训练
  -> 基础模型 / LoRA 严格对照评估
  -> LoRA 模型接入单个 Text-to-SQL Agent
  -> 可选：加入 API 教师作为能力参考
```

训练集只接收经过 MySQL 执行验证的只读 SQL。独立测试集由人工编写，不参与 API 合成。单个 Agent 负责知识检索、SQL 生成、安全检查、数据库执行、一次错误修复和结果展示；写操作、多语句和危险关键词会被拒绝。

## 配置

项目使用 `.env` 保存 MySQL 和 API 配置。接口遵循 OpenAI 兼容的 Chat Completions 形态，因此可通过修改 `LLM_API_BASE` 和 `LLM_MODEL` 切换 DeepSeek、OpenAI 兼容网关或智谱兼容接口。密钥不写入代码或文档。

## 验证

不配置 API Key 时，可运行 `python app.py --self-test` 验证知识检索、SQL 安全校验和表格渲染，也可使用 `--seed-only` 生成仅含人工种子的训练集。配置 API Key 后，教师模型只负责生成标准问题的语义等价改写，标准 SQL 不由 API 自由编造。

API 改写由裁判模型按种子批量审核。裁判必须检查数字、日期、筛选条件、排序方向、聚合口径和业务对象，返回“是否完全等价、置信度、理由”。只有判定等价且置信度达到阈值的样本自动进入训练集；裁判拒绝、缺失、格式错误或请求失败的样本全部丢弃。裁判可使用独立 API，未配置时复用教师 API。

独立裁判的地址、密钥和模型必须成组配置；部分配置直接报错，避免教师密钥被发送到错误的服务商地址。

严格的微调效果对比使用同一本地基础模型和“基础模型 + LoRA”。API 教师作为能力上限参考，可选加入三方评估，但不能替代微调前基线。评估以独立人工测试集上的 SQL 执行结果正确率为主：比较返回列数和数据值，忽略列别名；题目未要求排序时忽略行顺序。同时记录 JSON/SQL 提取率、SQL 可执行率、Agent 首次成功率、重试率、调用次数和耗时。

当前已经完成数据生成、自动裁判、训练和三方评估代码及轻量验证；完整 LoRA 训练和最终准确率报告需要用户在本机主动运行。训练目标目录非空时会直接停止，项目不会覆盖已有适配器。
